# Prism Browser: принятые решения

Журнал технических решений: что решили, от чего отказались и почему. Каждый этап дописывает сюда свои пункты.

## Цели производительности (проверяются на этапе 7)

| Метрика | Цель |
|---|---|
| Холодный старт до первого кадра | < 1 с |
| Адресная строка интерактивна после показа окна | < 300 мс |
| Переключение «тёплых» вкладок | < 100 мс |
| Кадры без пропусков | ≥ 99 % |

Оптимизацию принимаем только после замера «до/после» (DevTools, Impeller).

## Этап 1. Проект, тема, дизайн-система

### Окружение
- Flutter 3.47.7 (stable), Dart 3.13.5, Android SDK 36, JDK 17. Эмулятор с API 37 доступен.
- **Windows-сборка локально пока невозможна.** Visual Studio с нагрузкой «Desktop development with C++» не установлена. Кроме того, для плагинов Flutter нужен «Режим разработчика» Windows (поддержка симлинков). Оба пункта требуют системных изменений, поэтому выполнять их должен владелец машины. **Решение:** Windows собирается в GitHub Actions на `windows-latest` (см. раздел «Сборка в CI»), а готовая сборка запускается на этой машине.

### Идентификаторы
- Пакет `prism_browser`, Android applicationId `app.prism.browser`, платформы android и windows. Kotlin-namespace остался `app.prism.prism_browser` (так его создал шаблон; это внутреннее имя, на него ничего не завязано).

### Android-сборка
- `kotlin.incremental=false` в `android/gradle.properties`. Проект лежит на C:, а pub-cache на D:, и инкрементальные кэши Kotlin падают с «Could not close incremental caches» (пути на разных дисках). Модули плагинов маленькие, полная компиляция почти ничего не стоит.
- Debug APK собран, установлен на эмулятор (API 37) и запущен; скриншот: `docs/screenshots/stage1_android_glass_dark.png`. Стекло корректно размывает фон на Impeller, интерфейс идёт edge-to-edge под статус-бар.

### Переключатели (SegmentedButton)
- Выбранный сегмент обозначается галочкой, а не только заливкой: состояние не должно передаваться одним цветом.
- Чтобы три сегмента помещались на телефоне шириной 360–412 dp без переноса, в переключателе темы нет декоративных иконок. Сначала сохраняем подпись, иконку убираем.

### Структура слоёв
```
lib/
  domain/        модели без зависимостей от Flutter UI (AppearanceSettings)
  data/          репозитории и адаптеры (shared_preferences, позже drift, движки)
  application/   контроллеры и use cases (Riverpod Notifier)
  core/design/   дизайн-система: токены, абстракции Prism*, реализации стилей
  presentation/  экраны
  l10n/          ARB ru/en и сгенерированный код (lib/l10n/gen)
```

### Material вынесен в пакет `material_ui`
- Начиная с Flutter 3.47 Material живёт в отдельном пакете `material_ui`, а экосистема уже переехала на него (например, у `dynamic_color` 2.1 тип `ColorScheme` берётся из `material_ui`). Смешивание с `package:flutter/material.dart` даёт несовместимые типы.
- **Решение:** весь код импортирует `package:material_ui/material_ui.dart`. Миграция сделана штатным `dart fix --code=migrate_design_widgets`.
- Сгенерированный `AppLocalizations.localizationsDelegates` всё ещё ссылается на старые Material-локализации из `flutter_localizations`. Поэтому в `MaterialApp` подключаем `GlobalMaterialLocalizations.delegates` из `material_ui`.

### Система тем
- **Экраны не знают, какой стиль активен.** Они используют только `PrismSurface`, `PrismToolbar`, `PrismTabCard`, `PrismButton`/`PrismIconButton`, `PrismAddressField` и `showPrismSheet`. Каждый такой виджет делегирует отрисовку активной реализации `PrismDesign`, которую находит через `PrismDesignScope`.
- Реализации: `GlassDesign` и `MaterialDesign`, реестр лежит в `core/design/design_registry.dart`. **Третья тема** = значение в `PrismStyleId` + класс-наследник `PrismDesign` + строка в реестре.
- Токены (`PrismTokens`) оформлены как `ThemeExtension`. Поэтому при смене стиля или темы `AnimatedTheme` плавно интерполирует цвета, радиусы и силу размытия, без перезапуска. Структурная смена компонентов (капсула ↔ закреплённая панель) пока мгновенная; кроссфейд и морфинг появятся на этапе 6.
- Цветовая схема всегда строится через `ColorScheme.fromSeed`. Цвет обоев (Android 12+) или системный акцент Windows из `dynamic_color` берётся как seed. Так заполнены все роли M3 (`surfaceContainer*`), которые плагин сам не отдаёт.
- Тёмная тема по умолчанию. Адресная строка по умолчанию снизу на Android и сверху на Windows.
- Отказались от `ThemeMode` с нулевой длительностью для режима «уменьшить анимации»: `AnimatedTheme` всё равно запускается. Используем `themeAnimationStyle: AnimationStyle.noAnimation`.

### Liquid Glass (базовая версия этапа 1)
- Стекло применяется только к навигации и элементам управления, контент лежит на отдельном непрозрачном слое (рекомендация из ui-ux-pro-max для стиля «Liquid Glass»).
- `GlassMaterial` = `BackdropFilter` (blur σ 22) + тонировка + зеркальный блик сверху + градиентная обводка в 1 px. Шейдеры (`FragmentProgram`: линзирование по краю, хроматический сдвиг, адаптивный оттенок) появятся на этапе 6.
- **`BackdropFilter.grouped` / `BackdropGroup` пока не используем.** Сгруппированные фильтры дают артефакты, когда стеклянные поверхности перекрываются (лист поверх панели). Группировка рассматривается на этапе 7 и будет принята только по замерам.
- Контраст: тонировка подобрана так, чтобы основной и второстепенный текст давал ≥ 4.5:1 поверх фона Prism, включая пики цветных пятен. Это проверяет `test/design/contrast_test.dart` на 5 акцентах × 2 стиля × 2 темы.
- **Известное ограничение:** над произвольной веб-страницей (например, белой) фиксированная тонировка не гарантирует AA. Нужен адаптивный оттенок по яркости контента, он запланирован на этап 6.

### Кнопки и переключатели Liquid Glass (по образцу пользователя)
- **Линза (`GlassPill`)** — общая основа: градиентная подкрашенная заливка, светящаяся кромка (ярче сверху) и блик в верхней половине. Своего размытия у неё нет: линзы лежат на уже размытых панелях, а вложенный `BackdropFilter` удвоил бы стоимость и размытие.
- Тоны: `accent` (выбранный сегмент, основная кнопка, активная иконка), `neutral` (вторичные кнопки), `danger`, `recessed` (утопленная дорожка переключателя).
- **`PrismSegmented`** — новая абстракция. В Glass это утопленная капсула без разделителей, по которой пружинно (`PrismMotion.spring`, прерываемо) скользит акцентная линза; выбранный текст жирный и белый, остальные приглушены. В Material это штатный M3 `SegmentedButton` с галочкой.
- Отклик на наведение, фокус и нажатие сделан усилением свечения линзы, а не ripple. Кольцо фокуса для клавиатуры сохранено.
- **В тёмной теме все линзы из прозрачного стекла без подкраски** (по просьбе пользователя): белая полупрозрачная заливка, светлая кромка и блик. Выбранный пункт и основная кнопка выделяются более ярким стеклом, кромкой и жирным белым текстом, а не цветом. У опасной кнопки цветной только текст (осветлённый красный). Подкрашенный вариант (оттенок акцента в HSL) рассматривался и отклонён.
- В светлой теме у линзы осталась лёгкая подкраска акцентом.
- Контраст текста на всех тонах проверяется тестом (5 акцентов × 2 темы × фон и пики пятен) — ≥ 4.5:1. Тест ловил недобор для красного текста на прозрачном стекле (4,25), поэтому текст осветлён.

## Этап 2. Все экраны на моках

### Навигация и состояние
- **go_router 18.0.2** закреплён точно, а не через `^`: 18.1.0 вышел за 6 дней до выбора, это слишком свежо. 18.x уже работает на `material_ui`, поэтому страницы создаются корректно. Лицензия BSD-3.
- У каждого ключевого экрана есть URL: `/`, `/tabs`, `/bookmarks`, `/history`, `/downloads`, `/settings/...`, `/onboarding`. Браузерные панели открываются deep link'ом `/?panel=omnibox|menu|privacy|find&q=...`. Это пригодится для ссылок из системы, тестов и постеров.
- Пока онбординг не пройден, роутер перенаправляет на `/onboarding`.
- Доменные модели (`BrowserTab`, `Bookmark`, `HistoryEntry`, `DownloadItem`, `SearchEngine`, `PrivacySettings`, `SitePermission`) — чистый Dart. Пока данные берутся из `MockData`, на этапе 4 их заменят drift-репозитории с тем же интерфейсом провайдеров, и экраны менять не придётся.
- Работают в памяти уже сейчас: вкладки (новая, закрыть, закрепить, дублировать, инкогнито), пауза и возобновление загрузок, профили приватности (ручное изменение переключает профиль на «Свой»). Выбор поисковой системы сохраняется в prefs.
- Часы приложения вынесены в `clockProvider`, чтобы тесты и постеры давали одинаковый результат при каждом запуске.

### Новые элементы дизайн-системы
- `PrismBackground` (Glass: обои Prism; Material: плоская поверхность), `PrismIconBadge`, `PrismChip`, `PrismSearchField`, `PrismSegmented`. Каждый реализован в обоих стилях.
- `PrismTile`, `PrismSwitchTile`, `PrismSection` и каркас `PrismPage` не зависят от стиля и собраны из примитивов.
- `PrismToolbar.safeArea`: две нижние панели в стопке не удваивают системный отступ.
- Glass-панель сверху рисует мягкую подложку цвета фона под статус-баром, чтобы иконки статуса читались над белыми сайтами.
- Тумблеры в Glass монохромные, как на образце пользователя. Индикатор загрузки в тёмном стекле белый.

### Раскладки
- Телефон: адресная строка сверху или снизу (настройка), нижняя панель действий «назад / вперёд / новая вкладка / вкладки со счётчиком / меню», чип защиты с числом заблокированного в адресной строке.
- Ширина ≥ 840 dp (Windows): полоса вкладок с кастомными кнопками окна и десктопная панель инструментов. Горячие клавиши Ctrl+T/W/L/F/H/J/D/Tab и Esc уже работают. Перетаскивание вкладок и настоящие кнопки окна появятся на этапе 3 вместе с runner'ом.
- Android «назад» сначала закрывает открытую панель (`PopScope`), что совместимо с предиктивным «назад».
- Веб-контента пока нет: `MockWebPage` — макет статьи (собственный текст, не копия Википедии), с колонкой не шире 760 px на широких экранах.

### Честные ограничения в интерфейсе (предварительно, уточняются на этапах 3 и 5)
- DNS-over-HTTPS на Android: переключатель отключён и помечен «Недоступно в Android WebView — используйте системный „Частный DNS“». У WebView нет DNS на уровне приложения.
- Защита от fingerprinting помечена «работает частично» на обеих платформах, защита от утечки IP через WebRTC — на Android.

### Доступность (нашли тесты)
- `labeledTapTargetGuideline` проверяется на всех 13 маршрутах в обоих стилях. Тесты нашли и помогли исправить: фон-затемнение омнибокса без подписи для диктора, поле поиска M3 без имени, переполнение кнопки «Новая вкладка инкогнито» в нижней панели.
- Выбор передаётся не только цветом: галочка или иконка «выбрано» у профилей, поисковиков, акцентных цветов и периодов очистки истории.

### Постеры интерфейса
- `test/showcase/showcase_test.dart` (тег `showcase`) рисует из реального кода приложения 12 телефонных постеров (Liquid Glass / Material 3 × тёмная / светлая) и 2 десктопных. Результат лежит в `docs/showcase/`. Это не регрессионный тест, а презентация.
- Пересборка: `flutter test --tags showcase --update-goldens test/showcase`, затем скопировать `test/showcase/boards/*.png` в `docs/showcase/`.

## Этап 3. Веб-движок

### Выбор плагина
- **flutter_inappwebview 6.2.0-beta.3** (Apache-2.0) — один API для Android (System WebView) и Windows (WebView2).
  - Стабильная 6.1.5 (октябрь 2024) **не собирается** с текущим Android Gradle Plugin: использует удалённый `proguard-android.txt`. В бете 6.2.0-beta.3 (февраль 2026) это исправлено. Версия закреплена точно.
  - **Риск:** это бета. При выходе стабильной 6.2 переходим на неё.
- Отклонён `webview_flutter` (официальный): нет перехвата подресурсов (`shouldInterceptRequest`), без него невозможен сетевой блокировщик этапа 5. Под Windows его тоже нет.
- Отклонён `webview_windows`: не поддерживается с 2024 года, и это ещё одна зависимость. Windows-реализация inappwebview произошла от него и тоже рисует WebView2 в текстуру Flutter (`custom_platform_view/texture_bridge`).
- **path_provider** (BSD-3) добавлен для папки профиля WebView2.

### Архитектура
- `domain/engine`: интерфейсы `BrowserEngine` и `TabSession`, состояние `TabSessionState`, флаги возможностей `EngineCapabilities`. Исключение из чистоты слоя: `TabSession.buildView` возвращает виджет, потому что веб-вью и есть виджет.
- `data/engine`:
  - `InAppWebViewEngine` — общая база, от неё `AndroidEngine` и `WindowsEngine`;
  - `FakeEngine` — для тестов, постеров и неподдерживаемых платформ, рисует `MockWebPage`.
- Сессии создаются лениво (`sessionProvider` по id вкладки). Нативный WebView живёт через `InAppWebViewKeepAlive`, поэтому переключение вкладок не перезагружает страницу. Закрытие вкладки инвалидирует сессию и освобождает WebView.
- Заголовок и URL из движка синхронизируются обратно во вкладку (`updateMeta`).
- `UrlResolver` (домен, 14 групп тестов) разбирает ввод: адрес или поиск, `host:port`, localhost и IP (http), IDN в Punycode по RFC 3492 (собственная реализация, без зависимостей). Схемы `javascript:`, `data:` и `file:` из омнибокса не открываются никогда.
- Отображение IDN защищено от гомографов: домены с одним алфавитом показываются красиво (`пример.рф`), со смешанными алфавитами — в виде `xn--`, чтобы подмену вроде «аpple.com» с кириллической «а» было видно.

### Приватность движка
- **Чистый запуск без сетевых запросов.** Одна пустая вкладка со стартовой страницей, движок не навигирует, WebView не создаётся, пока его не нужно показать. Демо-данные этапа 2 (вкладки, история, закладки, статистика) включаются только флагом `demoDataProvider` в тестах и на постерах. Проверено тестом (`loadLog` пуст) и на эмуляторе.
- Настройки WebView по умолчанию: сторонние куки выключены; Safe Browsing выключен и в WebView, и в манифесте (он отправляет запросы в Google); смешанный контент запрещён; доступ к файлам и `content://` закрыт; геолокация и всплывающие окна выключены (разрешения будут на этапе 5); `isInspectable` только в debug.
- `android.webkit.WebView.MetricsOptOut = true`: WebView не отправляет метрики в Google.
- `usesCleartextTraffic = true`: HTTP-страницы должны оставаться доступными после предупреждения HTTPS-only, а само правило применяет Prism на этапе 5.

### Спайк: стекло над веб-контентом
- **Android, TLHC** (Texture Layer Hybrid Composition, `useHybridComposition: false`, по умолчанию): WebView рисуется в текстуру, и `BackdropFilter` по-настоящему размывает страницу под капсулами. Проверено на эмуляторе (API 37), снимки в `docs/screenshots/stage3_spike_tlhc_blur.png`.
- **Android, Hybrid Composition** (`--dart-define=PRISM_HC=true`): размытия нет, текст страницы резко просвечивает сквозь тонировку и смешивается с подписями панели (`stage3_spike_hc_no_blur.png`). Поэтому **автоматическая деградация**: если `capabilities.contentUnderChromeBlurs == false`, стекло над сайтом становится непрозрачной поверхностью той же формы (`stage3_hc_degraded_opaque.png`). HC оставлен как запасной режим для устройств, где TLHC работает плохо (например, проблемы с видео в SurfaceView).
- **Windows:** WebView2 рисуется в текстуру Flutter (texture bridge), поэтому размытие технически возможно. **Проверено** на сборке из CI (portable-zip запущен на Windows 11 с WebView2 155): en.wikipedia.org открывается, заголовок вкладки и полный адрес с замком обновляются; затемнение и стеклянная панель омнибокса рисуются поверх страницы, и контент под стеклом размыт. Скриншоты: `docs/screenshots/windows_*.png`.
- Известное ограничение (до этапа 6): тёмное стекло над белой страницей выглядит ровной серой капсулой. Это решит адаптивный оттенок по яркости контента.
- Раскладка: WebView нельзя «подложить» под верхнюю панель с внутренним отступом, поэтому он начинается под верхней панелью, а нижние панели плавают над страницей. Сворачивание панелей при скролле — этап 6.

### Честные возможности платформ (`EngineCapabilities`)

| | Android System WebView | Windows WebView2 |
|---|---|---|
| Размытие страницы под стеклом | да (TLHC), нет (HC → непрозрачно) | да (текстура, проверено) |
| Перехват запросов (блокировщик) | да (`shouldInterceptRequest`) | проверяется на этапе 5 |
| Изоляция куки по вкладкам | нет (один CookieManager) | нет |
| Инкогнито без записи на диск | **нет**: плагин не даёт Profile API, у инкогнито общие куки с обычными вкладками | проверяется на этапе 4 (InPrivate) |
| DNS-over-HTTPS | нет (только системный «Частный DNS») | проверяется на этапе 5 |

Пункты «нет» будут показаны в настройках как ограничения, без имитации работы.

### Проверено на устройстве (эмулятор Android 17 / API 37)
- Реальная страница ru.wikipedia.org открывается, капсулы размывают её.
- Омнибокс: `example.com` → «Перейти по адресу» → загрузка по HTTPS, URL и замок обновляются.
- Системный «назад» идёт по истории страницы и не закрывает приложение, «Вперёд» включается.
- Найдено на устройстве и исправлено:
  - `autofocus` поля омнибокса не срабатывал: фокус уже держал обработчик горячих клавиш. Теперь `FocusNode.requestFocus()` и выделение всего адреса;
  - для введённого адреса первой строкой предлагался поиск, теперь «Перейти по адресу»;
  - на чистом запуске грузились демо-вкладки; добавлены флаг `demoDataProvider` и пустые состояния.
- Лист защиты больше не показывает выдуманный «TLS 1.3» и всегда «защищено»: только фактическое состояние HTTPS страницы.

## Сборка в CI (GitHub Actions)

- Репозиторий: публичный `wepper6200/Prism-Browser`, как у Aurora-VPN-Client. Для публичных репозиториев минуты Actions бесплатны.
- `.github/workflows/build.yml` повторяет схему Aurora:
  - `test` (Ubuntu): `analyze --fatal-infos`, тесты без тегов `golden` и `showcase`;
  - `android` (Ubuntu): `scripts/build_android.sh` собирает APK по ABI и универсальный. Подпись берётся из секретов `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`; без них используется отладочный ключ;
  - `windows` (windows-latest): golden-тесты (не блокируют сборку, diff выгружается в артефакт), затем Inno Setup через choco и `scripts/build_windows.ps1 -Installer -FetchWebView2` (portable-zip и установщик);
  - `release`: черновик релиза по тегу `v*` со всеми артефактами.
- Установщик `installer/prism_browser.iss`:
  - ставится на пользователя без UAC (по желанию — для всех);
  - русский и английский языки;
  - опционально регистрирует Prism как браузер (`StartMenuInternet` + `Capabilities`/`URLAssociations` для http/https/.html), и его можно выбрать по умолчанию в параметрах Windows;
  - **WebView2 Runtime:** если его нет (Windows 10 без Edge), тихо ставит официальный Evergreen-загрузчик Microsoft, который CI скачивает при сборке. В Windows 11 Runtime уже есть.
- Профиль WebView2 (куки, кэш) лежит в `%LOCALAPPDATA%\Prism\Prism Browser\webview2` (`getApplicationCacheDirectory`), а не в Roaming: данные браузера не должны переезжать с перемещаемым профилем. При удалении приложения папка удаляется.

### Release Android: R8
- Включены `isMinifyEnabled` и `isShrinkResources` (требование ТЗ).
- **Найдено проверкой release-сборки на эмуляторе:** R8 вырезал Kotlin-методы, которые `shared_preferences_android` и `package:jni` вызывают через JNI по имени. Падал `SharedPreferencesWithCache.create` в `main()`, `runApp` не вызывался, и Android показывал «не отвечает» (ANR). Добавлены правила `android/app/proguard-rules.pro`: пакеты плагинов `sharedpreferences`, `pathprovider`, `jni`, а также `kotlin.**` и `kotlinx.coroutines.**` целиком (около 1,5 МБ; поиск по одному классу шёл по кругу: `CoroutineSingletons`, затем `Result$Failure`). После этого release-сборка запускается, сайт открывается.
- Вывод: перед выдачей артефактов release-сборку всегда проверять на устройстве, потому что debug R8 не использует.

### Windows: MSVC 14.5x (Visual Studio 2026) и корутины плагина
- Первый прогон в CI упал: `flutter_inappwebview_windows` использует экспериментальные корутины C++/WinRT (`/await`, `<experimental/coroutine>`), а в MSVC 14.51 это стало ошибкой STL1011.
- Временное решение по документации Microsoft: `_SILENCE_EXPERIMENTAL_COROUTINE_DEPRECATION_WARNINGS` в `windows/CMakeLists.txt` (наследуется плагинами). **Риск:** Microsoft обещает убрать этот режим совсем. До этого плагин должен перейти на C++20 `<coroutine>`; следим за обновлениями плагина.
- Из CI выходят portable-zip (13,6 МБ) и установщик (12,9 МБ, включая загрузчик WebView2), а также 4 APK.
- Ещё не сделано на Windows: свой заголовок окна (сейчас системный), рабочие кнопки окна в шапке, одиночный экземпляр, открытие ссылок из системы через аргументы командной строки. Это этапы 4 и 7.

## Правки перед этапом 4 (по отзыву пользователя)

### Своя поисковая система
- `CustomSearchTemplate.validate` (домен, тесты): ровно один `%s`, поддержка `{searchTerms}` из OpenSearch, без схемы подставляется https, IDN переводится в Punycode, схемы кроме http(s) запрещены. HTTP разрешён, но в форме показывается предупреждение «запросы видны в сети».
- Хранение в prefs (`search.custom.*`). При чтении шаблон проверяется заново: сохранённым данным не доверяем вслепую. `activeSearchEngineProvider` — единый источник для омнибокса, навигации и настроек. Удаление своего поисковика возвращает DuckDuckGo.
- Форма в листе: видимые подписи полей, подсказка с примером, проверка при потере фокуса и при сохранении (не на каждое нажатие), ошибка под полем. Общий стиль полей ввода добавлен в базовую тему (`inputDecorationTheme`).

### Встроенный поисковик Prism Search — убран
- Был сделан как поисковик по умолчанию: нативная страница с калькулятором, ответом Википедии, совпадениями на устройстве и кнопками веб-поиска (коммит 50f808d). По решению владельца проекта убран откатом. По умолчанию снова DuckDuckGo, выбор других поисковиков и «Свой URL» остаются. Код можно вернуть из истории git, если понадобится.

### Кнопки-иконки в Liquid Glass
- Видимая линза теперь 36 dp внутри зоны нажатия 48 dp: при наведении или выборе круг больше не выглядит раздутым рядом с вкладками и панелями.

### Лаг переходов между экранами (замерено)
- Стенд: `integration_test/transitions_perf_test.dart` через `flutter drive --profile` на эмуляторе Android (API 37). Сценарий: 3 круга по «Загрузки», «История», «Настройки» с возвратом. Метрики берутся из `FrameTiming` движка напрямую, потому что подключение к VM Service на этой машине ломает прокси. Эмулятор медленнее телефона, поэтому важны относительные числа.

| Вариант (Liquid Glass) | Отрисовка, среднее | p90 |
|---|---|---|
| Исходно | 138 мс | 194 мс |
| Карточки без `BackdropFilter` | 72 мс | 94 мс |
| + фон-картинка вместо градиентов + панели без размытия во время перехода | **42 мс** | **67 мс** |
| Material 3 (для сравнения) | 20 мс | 30 мс |

- Разбор затрат экспериментами: размытие карточек ~67 мс, размытие панелей ~22 мс, полноэкранные градиенты фона ~18 мс на кадр перехода.
- Принято:
  1. `GlassMaterial.blur = false` для карточек контента и карточек вкладок. Под ними мягкий фон, размытие визуально почти не заметно, а тонировка, кромка и блик остаются. Это совпадает с рекомендацией «стекло — для навигации и элементов управления».
  2. `PrismBackdrop` рисуется один раз в изображение шириной 96 px (`toImageSync`, кэш по цветам и пропорциям) и масштабируется.
  3. Панели во время анимации страницы используют плотную тонировку вместо живого размытия (`_RouteMotion` перестраивает виджет только при смене статуса анимации). После остановки размытие возвращается, а над сайтом в покое стекло остаётся настоящим.
- **Отклонено по замеру:** переход сдвигом в стиле iOS вместо zoom/fade для Glass — 42,5 мс против 42,1, p90 хуже (82 против 67). Остаётся предиктивный «назад».
- Остаток разницы с Material (~20 мс на эмуляторе) — отрисовка стеклянных деталей (градиенты линз, кромки). Вернёмся к нему на этапе 7 с замерами на реальном телефоне.

### Островки и «стеклянное почти всё» (Liquid Glass)
- Десктопная шапка разбита на островки-капсулы (`PrismSurfaceKind.island`): вкладки, кнопки окна, навигация, адресная строка, действия. Вся шапка — прозрачная подложка (`chrome`) поверх фона. В Material островки без оформления внутри обычной панели.
- Стекло получило двойную кромку (диагональный свет снаружи, тонкая внутренняя грань), отражение у нижнего края и внешнюю тень `BlurStyle.outer`: тень рисуется только снаружи формы и не затемняет прозрачную середину. Поля ввода, подсказки, слайдер и тумблеры в Glass тоже стеклянные, адресная строка — «утопленная» капсула.
- **Замер и урок по стенду.** Первый замер показал 52 мс против 42, но эмулятор в тот момент деградировал: следующий прогон оборвался, потому что эмулятор отвалился. После перезапуска эмулятора прогоны шли попеременно на одном и том же эмуляторе:

| Вариант (Glass), чистый эмулятор | Отрисовка, среднее | p90 |
|---|---|---|
| Прошлый коммит (до островков) | 3,2 мс | 5,5 мс |
| Островки, с тенями | 3,5 / 3,6 мс | 5,9 / 5,8 мс |
| Островки, без теней | 3,7 / 3,9 мс | 6,1 / 5,5 мс |
| Material 3 | 2,1–2,4 мс | 2,8–4,7 мс |

- Вывод: тени не стоят ничего измеримого, новое стекло добавляет ~0,4 мс на кадр. Тени оставлены. Абсолютные числа из таблицы выше (138→42 мс) снимались на долго работавшем эмуляторе и сравнимы только между собой. **Правило стенда:** сравнивать варианты только попеременными прогонами в одной сессии эмулятора, а не с числами из прошлых сессий.

### Деградация эффектов (`EffectsPolicy`)
- Стекло отключается (непрозрачная поверхность той же формы) при: системном высоком контрасте, режиме «Стекло: Выкл.», а в режиме «Авто» также на слабом устройстве или в режиме экономии энергии.
- Анимации отключаются при: настройке «Уменьшить анимации», системном `disableAnimations` и режиме экономии энергии.
- **Пока честно не определяются:** режим экономии энергии, слабое устройство и системное «уменьшить прозрачность» (Windows «Эффекты прозрачности»). Flutter их не отдаёт. На этапе 6 будет платформенный канал, а до тех пор флаги в `DeviceCapabilities` равны `false`.

### Шрифты и иконки
- **Inter 4.1** (OFL), статические начертания 400/500/600/700, лежат в `assets/fonts`. Загрузки из сети нет. Сабсетинг под кириллицу и латиницу запланирован на этап 7.
- **Иконки Phosphor 2.1 (MIT): шрифты лежат в проекте, пакет `phosphor_flutter` не используется.** Пакет заброшен (последний релиз в мае 2024) и не компилируется во Flutter 3.47, где `IconData` стал `final class`. Lucide (`lucide_icons_flutter` 4.0.0) отклонили: релизу 4 дня, это слишком свежо для зависимости. `PrismIcons` объявляет `const IconData` с кодами символов, поэтому tree-shaking шрифта в release работает, а сторонних зависимостей ноль.

### Тесты
- `flutter analyze` без замечаний: строгие касты, `strict-raw-types`, дополнительные правила линтера.
- Unit-тесты: `EffectsPolicy`, `AppearanceRepository` (round-trip, fallback неизвестных значений), контраст WCAG.
- Widget-тесты: смена стиля на лету, анимируемый lerp темы, мгновенная смена при reduce motion, `androidTapTargetGuideline` (48 dp), `labeledTapTargetGuideline`, английская локаль.
- Golden-тесты (`--tags golden`): галерея в обоих стилях, светлая и тёмная темы. Эталоны сгенерированы на Windows. Растеризация шрифтов зависит от ОС, поэтому в CI goldens проверяются только на `windows-latest`.
- Тест 48 dp нашёл реальную проблему: высота адресной строки была 40 px, исправлено.
